# 🎓 GradTrack

ระบบติดตามผลการศึกษาต่อของนักเรียน ม.6 โรงเรียนสุคนธีรวิทย์ — บันทึกผลสอบติดมหาวิทยาลัย
ออกรายงาน/การ์ดแสดงความยินดี และดูสถิติการเข้าศึกษาต่อรายปี

ข้อมูลนักเรียนและครูอ่านสดจาก **SchoolOS Public API** — GradTrack ไม่เก็บสำเนารายชื่อไว้เอง

---

## 🛠️ Tech Stack

| Layer | Technology |
|---|---|
| Frontend | React 19 + Vite + Tailwind/daisyUI |
| Backend | Node.js + Express 5 |
| Database | **PostgreSQL** (เกาะ `postgres-core` บน network `school-net`) |
| ข้อมูลนักเรียน/ครู | SchoolOS Public API (`/api/public/v1`) |
| Auth | JWT ที่ GradTrack ออกเอง (ตรวจรหัสผ่านผ่าน SchoolOS `/auth/verify`) |
| Deploy | Docker + Portainer, พอร์ต **3003** ใต้ path `/grad` |

## 🔐 สิทธิ์การใช้งาน

**ไม่มีการสร้างบัญชีในระบบนี้** — ครูทุกคนมาจาก SchoolOS และใช้รหัสผ่านของ SchoolOS เสมอ
ผู้ดูแลเป็นคนเลือกว่า *ครูคนไหนเข้าได้* และ *เข้ามาแล้วมีสิทธิ์แค่ไหน* ที่หน้า **จัดการผู้ใช้งาน**

| ใครล็อกอิน | role ใน GradTrack | ทำอะไรได้ |
|---|---|---|
| `teacher-admin` ของ SchoolOS | `admin` | ทุกอย่าง — **เข้าได้เสมอ ไม่ต้องอยู่ในรายชื่อ** |
| ครูที่ถูกเพิ่มไว้ + ตั้งเป็น `admin` | `admin` | ทุกอย่าง |
| ครูที่ถูกเพิ่มไว้ + ตั้งเป็น `teacher` | `teacher` | **ดูอย่างเดียว** — เปิดดูได้ทุกหน้า แต่บันทึก/แก้/ลบไม่ได้ |
| ครูที่**ไม่ได้**ถูกเพิ่มไว้ | — | ล็อกอินไม่ได้ (403) |
| นักเรียน | `student` | บันทึกผลสอบติดของตัวเอง (ไม่เกี่ยวกับรายชื่อนี้) |

รายชื่ออยู่ในตาราง `staff_access` — เพิ่ม/ถอด/เปลี่ยนสิทธิ์ผ่านหน้าเว็บเท่านั้น
ถอดสิทธิ์แล้ว **บัญชี SchoolOS ของครูไม่กระทบ** แค่เข้า GradTrack ไม่ได้ และเพิ่มกลับได้ทุกเมื่อ

> **สิทธิ์ admin เป็นของ SchoolOS เสมอ** — `teacher-admin` ผ่านด่านรายชื่อได้โดยไม่ต้องมีชื่ออยู่
> ในนั้น จึงไม่มีทางล็อกตัวเองออกจากหน้าที่ใช้แก้รายชื่อ (เคยเกิดมาแล้ว: เพิ่มครูคนแรกโดยลืม
> ใส่ตัวเอง → ประตูปิดทันทีทั้งที่เป็นผู้ดูแล) ถ้าอยากลดสิทธิ์ `teacher-admin` คนไหนเป็น
> ดูอย่างเดียวเฉพาะใน GradTrack ให้เพิ่มเขาเข้ารายชื่อแล้วตั้งเป็น `teacher` — แถวในรายชื่อทับ role
> ที่ SchoolOS ให้มา
>
> ⚠️ **ตาราง `staff_access` ว่าง = ยังไม่เปิดใช้งานรายชื่อ** ระบบจะกลับไปทำงานแบบเดิม
> (ครูทุกคนเข้าได้) และหน้าเว็บจะขึ้นแบนเนอร์เตือน จงใจให้เป็นแบบนี้ เพราะถ้าปิดตายตั้งแต่ตาราง
> ยังว่าง ครูทั้งโรงเรียนจะเข้าไม่ได้ทันทีที่ deploy · พอเพิ่มคนแรกเข้าไป การกันจะเริ่มทำงานทันที
>
> กันพลาดไว้อีกชั้น: ถอด/ลดสิทธิ์ตัวเองไม่ได้ และต้องเหลือ `admin` ในรายชื่ออย่างน้อย 1 คนเสมอ

บัญชี local ในตาราง `users` ไม่ผ่านรายชื่อนี้ — เป็น**ทางเข้าสำรองตอน SchoolOS ล่ม**
สร้างได้จากเครื่อง server เท่านั้น (`docker compose --profile seed run --rm seed`)
หน้าเว็บดูและลบได้ แต่**สร้างไม่ได้** และลบตัวสุดท้ายที่เป็น admin ไม่ได้

### รหัสผ่านนักเรียน
ทางหลักคือ **รหัสผ่าน SchoolOS ของนักเรียนเอง**
ทางเดิม `Skdw` + เลขบัตรประชาชน ยังเปิดอยู่ (`STUDENT_LEGACY_LOGIN=1`) เพื่อไม่ให้เด็กเข้าไม่ได้ในวันแรก
เมื่อย้ายกันครบแล้วให้ตั้ง `STUDENT_LEGACY_LOGIN=0` — รหัสผ่านที่เดาได้จากเลขบัตรประชาชนไม่ปลอดภัย

### 🔁 Silent SSO — ล็อกอิน SchoolOS ไว้แล้วเข้าได้เลย

เปิด `schoolos.sukhon.ac.th/grad` ขณะที่ยังล็อกอิน SchoolOS อยู่ → **เข้าระบบเลย ไม่เห็นหน้า login**
ถ้ายังไม่ได้ล็อกอิน (หรือ SchoolOS ไม่ตอบ) ก็เห็นฟอร์มตามปกติ ใช้ได้ทั้งครูและนักเรียน

```
เบราว์เซอร์                         GradTrack (server)            SchoolOS Users
   ├─ GET /users/api/auth/handoff?audience=grad ─────────────────▶ code (60 วิ ครั้งเดียว)
   ├─ POST /grad/api/auth/sso {code} ─▶
   │                                  ├─ POST /auth/handoff/redeem ─▶ ตัวตนผู้ใช้
   │                                  ├─ ตรวจรายชื่อครู / รุ่นนักเรียน แล้วออก JWT ของเรา
   │◀─────────────────────────────────┤
```

- **API key ไม่เคยออกจาก server** — เบราว์เซอร์ถือแค่โค้ดที่อายุ 60 วินาที ใช้ได้ครั้งเดียว
  และไร้ค่าถ้าไม่มี key ของ GradTrack คู่กัน (cookie ของ SchoolOS เป็น HttpOnly หน้าเว็บอ่านไม่ได้)
- **ด่านเดิมยังอยู่ครบ** — ตัวตนที่ได้จาก SSO ไม่มี `active`/`status` และไม่บอกว่าเป็น `teacher-admin`
  (API.md §4.11) ระบบจึงอ่านทะเบียนครู/นักเรียนเองทุกครั้ง แล้วผ่านรายชื่อ `staff_access` และ
  เกณฑ์ "รุ่นที่เพิ่งจบ" ชุดเดียวกับการล็อกอินด้วยรหัสผ่าน — เข้าทาง SSO ไม่ได้สิทธิ์พิเศษกว่า
- อายุ token ที่ออกให้ถูกตัดไม่ให้เกิน session ของ SchoolOS ที่เหลืออยู่
- **ต่ออายุ session ของ SchoolOS ให้ทุก 10 นาที เฉพาะตอนที่ผู้ใช้ขยับจริงในรอบนั้น** —
  SchoolOS ไม่นับการใช้งานในระบบเราเป็น activity (§4.10 จงใจ) ถ้าไม่ต่อให้ ครูที่นั่งทำงาน
  ในนี้จนเกิน idle window ของ SchoolOS จะหลุดเงียบ ๆ แล้วรอบหน้าต้องกรอกรหัสใหม่ทั้งที่
  เพิ่งใช้งานอยู่แท้ ๆ · ที่ต้องดู "ขยับจริง" ด้วย เพราะถ้าดูแค่ว่า session ยังไม่หมดอายุ
  แท็บที่เปิดค้างไว้เฉย ๆ จะได้ต่ออายุไปเรื่อย ๆ = ยืด session ให้คนที่ลุกจากเครื่องไปแล้ว
- **ไม่**ดึงกลับเข้าระบบอัตโนมัติหลัง**เพิ่ง**ถูกเตะออกเพราะ token หมดอายุ/โดน 401 —
  ต้องกรอกเอง ไม่งั้นเสี่ยงวนเป็นวง (เข้าได้ → โดน 401 อีก → เข้าใหม่ → ...)
  · นับเฉพาะ "เพิ่งโดน" (ภายในหนึ่งช่วง idle timeout) เท่านั้น — ไม่ใช่ "เคยโดนเมื่อไหร่ก็ได้"
  ไม่งั้นเบราว์เซอร์ที่เคยหมดเวลาสักครั้งจะไม่ได้ SSO อีกเลยจนกว่าจะกรอกรหัสด้วยมือ
  · ข้อยกเว้นที่ไม่ต้องกรอกเอง: หลุดเพราะ **ตัวตนฝั่ง SchoolOS เปลี่ยน** (ข้อถัดไป)
  มีคนใหม่อยู่หน้าเครื่องอยู่แล้ว การบังคับให้พิมพ์ซ้ำไม่ได้เพิ่มความปลอดภัยอะไร
  · และหลุดเพราะ **idle** — ตัวคัดกรองคือ SchoolOS เอง: ขอโค้ด handoff ได้ก็ต่อเมื่อ
  session ของแพลตฟอร์มยังอยู่ (= ยังทำงานอยู่ในระบบอื่นด้วย session เดียวกัน)
  ลุกจากเครื่องไปจริง session ฝั่งโน้นหมดตามไปด้วย → ได้ฟอร์มพร้อมข้อความบอกเหตุผลเหมือนเดิม

#### ตรวจตัวตนสดทุกครั้งที่โหลดหน้า (`components/SessionGuard.jsx`)

session ของเรากับของ SchoolOS เป็น**คนละใบ** — handoff แค่ "คัดลอกตัวตน" มาตอนหนึ่ง
ไม่ได้ผูกสองใบเข้าด้วยกัน ถ้าเชื่อ token ของเราไปจนหมดอายุ พอมีคนล็อกอินใหม่ที่ portal
token ใบเดิมก็ยัง valid และยังชี้ไปที่คนเก่า → **คนใหม่เห็นข้อมูล/สิทธิ์ของคนเก่า**
บนเครื่องส่วนกลาง กด hard refresh ก็ไม่ช่วย (การลดอายุ token ทำให้ "ผิดสั้นลง" ไม่ได้ทำให้ "ไม่ผิด")

การผูกจึงเป็นสิ่งที่ระบบเราต้องทำเอง:

1. ตอนแลก handoff เก็บ `sub` ของ SchoolOS ไว้ใน JWT เป็น claim `ssoSub` (ดิบ ๆ ไม่แปลง)
   — `id` ในฐานข้อมูลเราเทียบอะไรกับฝั่งโน้นไม่ได้เลย
2. หน้าเว็บถาม `GET /users/api/auth/session` (cookie ล้วน · ไม่แตะ DB · **ไม่**ต่ออายุ idle
   window ของ SchoolOS จึงยิงบ่อยได้) ตอน **โหลดหน้า · กลับมาที่แท็บ · ทุก 60 วิ**
3. ไม่ตรง → เป็นคนใหม่ก็แลก handoff ใหม่ให้เงียบ ๆ แล้ว `location.assign()` ทั้งหน้า
   (ห้าม `router.push` — จะ re-render จาก cache ที่สร้างไว้ให้คนเก่า) · ไม่มีใครล็อกอินแล้ว
   ก็ล้าง session แล้วไปหน้า login

> ⚠️ กฎที่ห้ามพลาดเวลาแก้โค้ดส่วนนี้
> - **"ถามไม่ได้" ≠ "ไม่มีใครล็อกอิน"** — เน็ต/CORS/service ล่ม ต้องไม่ทำอะไรเลย
>   ถ้าเหมารวมกับ `valid:false` เน็ตกระตุกทีเดียวจะเตะทั้งโรงเรียนออกพร้อมกัน
>   ("ไม่มีใครล็อกอิน" คือ HTTP 200 + `valid:false` — ต้องอ่านจาก field ไม่ใช่ status)
> - ใช้กับ session ที่ `via === 'sso'` เท่านั้น — บัญชี local และคนที่กรอกรหัสผ่านเองไม่มี
>   session ฝั่งแพลตฟอร์มให้เทียบ ถ้าเอามาใช้ด้วยจะเตะพวกเขาออก และวันที่ SchoolOS ล่ม
>   ทางเข้าสำรองจะล่มตามไปด้วย
> - ทุกจุดที่ออก/ต่ออายุ token ต้องผ่าน `signToken()` ซึ่งกรอง claim ผ่าน `config/identity.js`
>   ให้ · ลืมคัดลอก `ssoSub` ที่ไหนสักที่ = บั๊กกลับมาเงียบ ๆ ตอนต่ออายุครั้งแรก
>   (`cd server && npm test` มีเทสคุมไว้)
> - ตอน `npm run dev` ที่คนละ origin กับ Users จริง การถามจะคืน null ตลอด = **ไม่มีการตรวจ**
>   ไม่ใช่ของพัง · จะเทสจริงต้องรัน Users ในเครื่อง + ให้ผู้ดูแลใส่ origin ของ dev
>   ลง `SSO_ALLOWED_ORIGINS`
- **กด "ออกจากระบบ" = ออกจาก SchoolOS ทั้งแพลตฟอร์มด้วย** จงใจให้เป็นแบบนี้ ถ้าล้างแค่ฝั่ง
  GradTrack cookie ของ SchoolOS จะยังอยู่ แล้วรอบถัดไป SSO ก็พากลับเข้ามาเอง = ล็อกเอาต์ไม่ได้จริง
  บนเครื่องส่วนกลาง
- **ไม่มี session = กลับไปเข้าระบบที่ SchoolOS** ทั้ง session ที่จบเอง (หมดเวลา /
  token หมดอายุ / 401 / SchoolOS ออกไปแล้ว) และคนที่เปิด `/grad` ตรง ๆ โดยไม่เคยล็อกอิน
  — GradTrack ไม่ใช่ประตูหน้าของตัวเอง ทางเข้าปกติคือล็อกอินที่ SchoolOS แล้วเดินเข้ามา
  ปลายทางคือ `SCHOOLOS_PORTAL_URL` (`bounceAfterSessionEnd()` / `leaveToSchoolOS()`
  ใน `utils/session.js` · โหลดหน้าใหม่ทั้งหน้าเสมอ ห้ามใช้ router เพราะหน้าที่ค้างอยู่
  ถูก render ไว้ให้คนเก่า) · **ไม่**เรียก `/users/api/auth/logout` — หมดเวลาใน GradTrack
  ไม่ควรเตะครูออกจากแพลตฟอร์มทั้งใบ เขาอาจกำลังทำงานในระบบอื่นอยู่
  > **เงื่อนไขคือ "ขอโค้ด handoff ไม่ได้" ล้วน ๆ** (`trySilentLogin()` คืน `null`) ครอบทุก
  > เหตุผล ไม่ใช่แค่ตอนที่ยืนยันได้ว่าไม่มีใครล็อกอิน — เดิมตรงนี้ยืนกรานให้
  > `GET /api/auth/session` ตอบ `valid:false` ก่อน ผลคือทุกกรณีที่ "ถามไม่ได้" (Users ตอบช้า /
  > CORS / 429 ตอนคนเปิดพร้อมกันทั้งห้อง) ไปจบที่ฟอร์ม ทั้งที่รหัสผ่านของครูและนักเรียน
  > อยู่ที่ SchoolOS ไม่ใช่ที่นี่ ฟอร์มนั้นจึงช่วยเขาไม่ได้เลยสักคน
  >
  > ⚠️ ที่ทำให้ยอมพาออกไปกว้างขนาดนี้ได้ คือทางถอยที่**มองเห็นด้วยตา** — ห้ามถอดทั้งสามอย่าง
  > ไม่งั้นคนที่ไม่มี session ฝั่ง SchoolOS จะเดินวนระหว่างสองเว็บโดยไม่มีทางเห็นฟอร์มเลย
  > (บัญชี **admin local ซึ่งเป็นทางเข้าสำรองตอน SchoolOS ล่ม** · ครู/นักเรียนที่กรอกรหัสเอง ·
  > ตอน `npm run dev` ที่ยังไม่ได้ชี้ base มาที่ Users จริง)
  > - **หน้าจอบอกก่อนพาไป** ค้างไว้ 2.5 วิ พร้อมลิงก์ "เข้าสู่ระบบที่หน้านี้แทน" — กดแล้ว
  >   อยู่ที่ฟอร์มได้ทั้งหน้านี้และรอบถัดไป
  > - `bouncedToSchoolOSRecently()` — เด้งได้รอบเดียวต่อ 5 นาที รอบถัดไปเห็นฟอร์ม · ธงถูก
  >   ประทับตั้งแต่ตอน**ตัดสินใจ** (รวมตอนกดอยู่ต่อ) และถูกล้างตอนล็อกอินสำเร็จ จึงนับเฉพาะ
  >   ช่วงที่ยังเข้าไม่ได้จริง ๆ
  > - `/grad/login?local=1` — ขอฟอร์มมาเอง ไม่เด้งไม่ว่ากรณีใด
- **ข้อยกเว้นเดียวคือ `SSO_DENIED`** (ล็อกอิน SchoolOS อยู่จริงแต่บัญชีนี้ไม่มีสิทธิ์ใช้
  GradTrack — ลาออก / จบไปนานแล้ว / ไม่อยู่ในรายชื่อครู) จบที่ฟอร์มของเราพร้อมข้อความเสมอ
  ส่งกลับไปก็เท่ากับส่งกลับไปหาสิ่งที่เขามีอยู่แล้ว แล้วเดินกลับเข้ามาโดนปฏิเสธซ้ำโดยไม่มี
  ใครบอกสักครั้งว่าเพราะอะไร (`STAY_ON_LOGIN_REASONS` ใน `utils/session.js`)
- **แท็บอื่นหลุดตาม ก็ไปที่เดียวกัน** — อีกแท็บล็อกเอาต์/หมดเวลา แท็บที่เหลือหลุดตามผ่าน
  event `storage` แล้วใช้ `leaveAfterSessionEnd(getLogoutReason())` ตัวเดียวกับแท็บต้นทาง
  (เดิมพาไป `/login` ตายตัว = การหลุดครั้งเดียวพาแท็บหนึ่งไป SchoolOS แต่แท็บที่เหลือ
  ไปจอดที่ฟอร์ม)
- **ปุ่ม "ออกจากระบบ" ไปไกลกว่านั้น** — กดออกเอง = ตั้งใจออกจากแพลตฟอร์มด้วย จึง navigate
  ไป `/users/api/auth/logout?next=<SCHOOLOS_PORTAL_URL>` ครั้งเดียว (เชื่อถือได้กว่า
  ยิง POST ทิ้งไว้แล้วรีบเปลี่ยนหน้า ซึ่งเบราว์เซอร์ยกเลิกกลางคันได้) · ระหว่างรอเปลี่ยนหน้า
  (ต้องอ่านคอนฟิกก่อน = async) `AuthProvider` คลุมจอด้วย "กำลังออกจากระบบ…" ไว้ ไม่งั้น
  `ProtectedRoute` เห็น `user` เป็น `null` แล้วพาไปหน้า login ของเรา = เห็นฟอร์มแวบหนึ่ง
  ทุกครั้งที่กดออก — ด้วยเหตุผลเดียวกัน หน้าที่มีปุ่มออกจากระบบห้ามต่อท้ายด้วย
  `navigate('/login')`

**สิ่งที่ต้องให้ผู้ดูแล SchoolOS ตั้งให้ (ตั้งครบแล้วทั้งคู่)** — ขาดข้อไหนก็แค่ SSO ไม่ทำงาน ระบบไม่พัง

1. API key ของ GradTrack ต้องมี scope `auth:handoff` **และ** ช่อง "ระบบปลายทาง (audience)" = `grad`
2. `https://schoolos.sukhon.ac.th` อยู่ใน `SSO_ALLOWED_ORIGINS` ของ Users (ต้องตรงเป๊ะ ห้ามมี `/` ปิดท้าย)

ตรวจเองได้ที่ `curl -H "X-API-Key: sk_live_…" <base>/api/public/v1/me` → ต้องเห็น `auth:handoff`
ใน `scopes` และ `"handoffAudience": "grad"` · ตอนคอนเทนเนอร์สตาร์ทก็เตือนให้ถ้าตั้งไม่ครบ

ปิดฟีเจอร์นี้ได้ด้วย `SSO_SILENT_LOGIN=0` (ทุกคนกลับไปกรอกรหัสเองเหมือนเดิม)

### ⏱️ หมดเวลาใช้งาน (session timeout)

ผู้ใช้หลุดจากระบบเมื่อเข้าเงื่อนไขใดเงื่อนไขหนึ่ง — ใช้กับทั้งครูและนักเรียนเหมือนกัน

| ชั้น | ค่าเริ่มต้น | ตั้งที่ |
| --- | --- | --- |
| ไม่ได้ใช้งาน (idle) | 15 นาที | `IDLE_TIMEOUT_MINUTES` ใน [`client/src/utils/session.js`](client/src/utils/session.js) — แก้แล้วต้อง build ใหม่ |
| อายุ token | 8 ชั่วโมง | `JWT_EXPIRES_IN` (env) — **ต่ออายุให้อัตโนมัติถ้ายังนั่งทำงานอยู่** (ดูด้านล่าง) |

**ไม่เตะคนที่กำลังทำงานอยู่กลางคัน** — เมื่อ token เหลืออายุน้อยกว่า 15 นาที **และ**
ผู้ใช้เพิ่งขยับจริงภายใน 5 นาทีที่ผ่านมา หน้าเว็บจะขอ `POST /api/auth/refresh` ให้เอง
ครูที่กรอกข้อมูลค้างอยู่จึงไม่ถูกเตะออกแล้วข้อมูลหาย

> ตัวที่คุมจริงจึงกลายเป็น **idle 15 นาที** ไม่ใช่เพดาน 8 ชั่วโมงอีกต่อไป — ตั้งใจให้เป็นแบบนี้
> เพราะเคสที่เพดาน 8 ชั่วโมงเคยกัน (ลืมล็อกเอาต์ทิ้งไว้ในห้องพักครู) ถูก idle timeout กัน
> ได้ตรงกว่าอยู่แล้ว · ต่ออายุได้เฉพาะตอนที่ token ยัง valid — หมดอายุไปแล้วต่อไม่ได้
> ต้องล็อกอินใหม่ · แท็บที่เปิดค้างไว้เฉย ๆ ไม่นับว่า "ทำงานอยู่" จึงไม่ถูกต่ออายุให้

> ⚠️ **idle ของ GradTrack ต้องไม่ยาวกว่า `SESSION_IDLE_MINUTES` ของ SchoolOS Users**
> ไม่งั้นจะเจอสภาพ "ยังอยู่ใน GradTrack แต่ SchoolOS ตายไปแล้ว" — ผู้ใช้ต้องกรอกรหัสใหม่
> ทั้งที่เพิ่งใช้งานอยู่แท้ ๆ · ข้อความที่หน้า login อ้างอิงค่าเดียวกันนี้ ไม่ต้องแก้ตามสองที่

**"ไม่ได้แตะ GradTrack" ≠ "ลุกจากเครื่องไปแล้ว"** — ครูมักเปิดหน้านี้ค้างไว้แล้วไปทำงาน
ในระบบอื่นของ SchoolOS ด้วย SSO ตัวเดียวกัน อาการที่เคยเจอคือกลับมาแล้วเจอ
"ไม่ได้ใช้งานเกิน 15 นาที" ทั้งที่ใช้งานแพลตฟอร์มอยู่ตลอด นาฬิกา idle จึงมี **สองเข็ม**
และหมดเวลาก็ต่อเมื่อเงียบทั้งคู่:

| เข็ม | เดินหน้าเมื่อ |
| --- | --- |
| แท็บนี้ | ผู้ใช้ขยับจริงในหน้า GradTrack |
| แพลตฟอร์ม | `GET /users/api/auth/session` ตอบว่าเป็น**คนเดิม**และยังล็อกอินอยู่ (ถามอยู่แล้วทุก 60 วิ โดย `SessionGuard` และถามอีกครั้งตอนเข็มแรกครบกำหนด) |

> เข็มที่สองเดินหน้าได้เฉพาะตอน **ได้คำยืนยัน** เท่านั้น — ถามไม่ได้ (เน็ต/SchoolOS ล่ม)
> หรือเป็นคนอื่นแล้ว = เข็มค้างที่เดิมแล้วหลุดตามกำหนด ตั้งใจให้ผิดไปทางเตะออก
> ไม่งั้น probe ที่พังจะกลายเป็น session อมตะ · session ที่ไม่ได้มาทาง SSO (บัญชี local /
> กรอกรหัสผ่านเอง) ไม่มีเข็มที่สอง — ยังเป็น idle 15 นาทีเต็มเหมือนเดิม
> · เข็มนี้ห้ามให้ event ในหน้าเว็บเขียน ไม่งั้นจะเกิดวงจร "แท็บค้าง → ต่ออายุ SchoolOS →
> แพลตฟอร์มยังสด → แท็บไม่หลุด" ซึ่งทำให้ session ทั้งสองใบไม่มีวันหมดอายุ

- นาฬิกา idle นับข้าม reload และข้ามแท็บ (เก็บใน `localStorage`) — ขยับแท็บไหนก็ต่ออายุให้ทุกแท็บ
- ตัวจับเวลาฝั่งหน้าเว็บเป็นแค่ **การล็อกหน้าจอที่เปิดค้างไว้** ไม่ใช่มาตรการความปลอดภัย
  ตัวที่บังคับจริงคืออายุ token ที่ `verifyToken` ตรวจทุก request (ตอบ 401 `code: TOKEN_EXPIRED`)
- หลุดแล้วหน้า login จะขึ้นข้อความบอกเหตุผล ไม่ใช่เด้งออกเฉย ๆ โดยไม่รู้ว่าเกิดอะไรขึ้น

รหัสผ่าน / คีย์ทั้งหมดอยู่ใน `.env` หรือ stack env ของ Portainer **เท่านั้น**
ห้ามเขียนลงในโค้ดหรือ `docker-compose.yml` ที่ commit ขึ้น git

## 🗄️ ฐานข้อมูล

Migration อยู่ที่ [`server/database/postgres/`](server/database/postgres/) รันอัตโนมัติทุกครั้งที่สตาร์ท

**กฎเหล็ก: additive เท่านั้น** — ห้ามมี `DROP TABLE` / `DROP COLUMN` / `TRUNCATE` / `DELETE FROM`
เพราะ deploy ผ่าน Portainer เป็น push แบบไม่ถามใครก่อน ถ้ามี statement ที่ทำข้อมูลหายมันจะหายเงียบ ๆ
`server/database/migrate.js` ตรวจไฟล์ให้ก่อนรัน — เจอคำต้องห้ามจะหยุดทันที

ไฟล์ migration ต้อง idempotent (`IF NOT EXISTS` ทุกที่) เพราะรันซ้ำทุกรอบที่สตาร์ท
เพิ่มคอลัมน์ใหม่ให้แก้ไฟล์เดิมได้เลย ไม่ต้องตั้งชื่อไฟล์ใหม่

รันเดี่ยว ๆ: `cd server && npm run db:migrate`

## 🏫 คลังมหาวิทยาลัย (seed)

รายชื่อมหาวิทยาลัย / โลโก้ / คณะ / สาขา / หลักสูตร ติดไปกับ image เป็นข้อมูลตั้งต้น
ระบบที่ deploy ใหม่จึงมีคลังครบตั้งแต่เปิดครั้งแรก ไม่ต้องไป import Excel หรือกดซิงค์วิกิพีเดียเอง

| ไฟล์ | คือ |
|---|---|
| [`server/database/seeds/catalog.json.gz`](server/database/seeds/) | มหาวิทยาลัย + คณะ + หลักสูตร (ซ้อนเป็นชั้น ไม่เก็บ id) |
| `server/database/seeds/logos/` | ไฟล์โลโก้ — ต้องอยู่ที่นี่ เพราะ `server/uploads/` ติด `.gitignore` + `.dockerignore` |
| [`server/database/seed-catalog.js`](server/database/seed-catalog.js) | ตัว seed — `index.js` เรียกตอนสตาร์ทต่อจาก migration |

**ลงมือเฉพาะตอนตาราง `universities` ว่างเปล่า** — ถ้าแอดมินตั้งใจลบมหาวิทยาลัยทิ้ง
restart รอบหน้าจะไม่เอากลับมาให้ และไม่มี `DELETE` อยู่ในตัว seed เลย ของที่แก้ไว้ไม่หาย

```bash
npm run seed:catalog              # ลงให้เฉพาะตอนตารางว่าง (เหมือนตอนสตาร์ท)
npm run seed:catalog -- --force   # เติมทับของที่มีอยู่ (ไม่ลบอะไรทิ้ง กันแถวซ้ำให้)
```

ปิด seed อัตโนมัติ: ตั้ง `CATALOG_SEED=off` ใน stack env

### อัปเดตไฟล์ seed

## 💾 สำรอง & กู้คืนข้อมูล

หน้า **สำรอง/กู้คืนข้อมูล** (เมนูล่างสุด — **admin เท่านั้น**) ทำได้ครบในหน้าเดียว:
สำรองลง server · ดาวน์โหลดเก็บไว้เอง · อัปโหลดไฟล์เก่ากลับขึ้นมา · กู้คืน · ลบ

ไฟล์สำรอง 1 ไฟล์ = `.tar.gz` มาตรฐาน (แตกดูด้วย `tar` / 7-Zip ได้ ไม่ใช่ฟอร์แมตลับ)

```
manifest.json        สร้างเมื่อไร โดยใคร มีอะไรอยู่ข้างในบ้าง (entry แรกเสมอ)
data/<table>.json    ทุกแถวของแต่ละตาราง
uploads/…            รูปนักเรียน / โลโก้ / พื้นหลังการ์ด (เลือกได้ว่าจะรวมไหม)
```

| อยู่ในไฟล์ | **ไม่**อยู่ในไฟล์ |
|---|---|
| ทุกตารางของ GradTrack (12 ตาราง) | ชื่อ/ชั้น/ห้องของนักเรียนและครู — อ่านสดจาก SchoolOS เสมอ |
| ไฟล์ใน `server/uploads/` | ค่าใน `.env` (รหัส DB / `JWT_SECRET` / API key) |
| | โครงสร้างตาราง — schema มาจาก migration ตอนสตาร์ทเสมอ |

เก็บแต่ "ข้อมูล" ไม่เก็บ schema โดยตั้งใจ → กู้ไฟล์เก่าเข้าระบบเวอร์ชันใหม่ได้
(ตอนใส่กลับจะใช้เฉพาะคอลัมน์ที่มีอยู่จริง คอลัมน์ที่เพิ่มมาทีหลังได้ค่า default)
ซึ่งใช้ได้เพราะ migration เป็น additive อยู่แล้ว

### กู้คืน 2 แบบ

| โหมด | ทำอะไร | ใช้ตอนไหน |
|---|---|---|
| **เติมเฉพาะที่ยังไม่มี** (ค่าเริ่มต้น) | แถวที่ชนคีย์ถูกข้าม ของเดิมไม่ถูกแตะเลย | เผลอลบข้อมูลบางส่วน อยากได้กลับมาเฉย ๆ |
| **แทนที่ทั้งหมด** | ล้างตารางที่อยู่ในไฟล์ แล้วใส่ของในไฟล์แทน | ย้อนทั้งระบบกลับไปเป็นวันที่สำรองไว้ |

- ทั้งสองแบบอยู่ใน transaction เดียว — พังกลางคันข้อมูลกลับไปเหมือนเดิมทั้งหมด
- **ระบบสำรองของปัจจุบันให้อัตโนมัติก่อนกู้คืนทุกครั้ง** (`gradtrack-prerestore-…`)
  กู้ผิดไฟล์ก็ยังย้อนกลับได้ ไฟล์กลุ่มนี้ไม่ถูกลบตามโควตา
- ไฟล์ใน `uploads/` เขียนทับชื่อที่ซ้ำ แต่**ไม่ลบ**ไฟล์ที่ไม่มีในไฟล์สำรอง
  (รูปที่เพิ่งอัปหลังวันสำรองจะไม่หายเพราะกดกู้คืน)
- ตาราง `SERIAL` ถูก `setval` ใหม่หลังใส่ข้อมูล ไม่งั้นแถวถัดไปที่บันทึกจะชนคีย์ทันที

### ที่เก็บและโควตา

ไฟล์อยู่ใน named volume `gradtrack-backups` (`/app/server/backups`) — **ไม่หายตอน redeploy**
แต่ก็อยู่เครื่องเดียวกับระบบ ของสำคัญจริงควรกดดาวน์โหลดออกมาเก็บที่อื่นด้วย

| ตัวแปร | ค่าเริ่มต้น | คือ |
|---|---|---|
| `BACKUP_KEEP` | `20` | เก็บไฟล์ที่ระบบสร้างเองไว้กี่ไฟล์ (0 = ไม่ลบเลย) — ที่เกินถูกลบตอนสำรองครั้งถัดไป |
| `BACKUP_MAX_UPLOAD_MB` | `1024` | ขนาดไฟล์สูงสุดที่อัปโหลดกลับเข้ามาได้ |
| `BACKUP_DIR` | `server/backups` | ปกติไม่ต้องตั้ง |

โควตานับเฉพาะไฟล์จากปุ่ม "สร้างไฟล์สำรอง" — ไฟล์ที่แอดมิน**อัปโหลดเข้ามาเอง**
และไฟล์ **ก่อนกู้คืน** ถือว่าตั้งใจเก็บ ไม่ถูกลบอัตโนมัติ

หยิบไฟล์ออก/ใส่กลับจากเครื่อง server ตรง ๆ ก็ได้ (ไม่ต้องผ่านหน้าเว็บ):

```bash
docker cp gradtrack-app:/app/server/backups ./backups          # เอาออกมาทั้งโฟลเดอร์
docker cp ./backup.tar.gz gradtrack-app:/app/server/backups/   # ใส่กลับเข้าไป
```

ทุกการสร้าง/ดาวน์โหลด/อัปโหลด/กู้คืน/ลบ ถูกบันทึกใน **Activity Log** เสมอ

## 🧭 กฎเรื่อง path / base path

แอปเสิร์ฟใต้ subpath (`schoolos.sukhon.ac.th/grad/`) โดย nginx **คง prefix ไว้** ไม่ตัดออก

- โค้ดใหม่ที่ประกอบ URL ของหน้าเว็บหรือไฟล์ใน `public/` **ต้องผ่าน `withBase()`**
  ([`client/src/utils/withBase.js`](client/src/utils/withBase.js))
- **ห้ามอ่าน `import.meta.env.BASE_URL` ดิบ ๆ** กระจายตามไฟล์ — ใช้ `withBase()` ที่เดียว
  (ยกเว้น `basename` ของ `<BrowserRouter>` ซึ่งเป็นตัวนิยาม base เอง)
- URL ของ API **ไม่ต้อง**ใช้ `withBase()` — ใช้ `api` (axios) ที่ตั้ง baseURL ไว้แล้ว
- asset ใหม่ใน `client/public/` ถูกเสิร์ฟใต้ base ให้อัตโนมัติโดย express
  (SPA fallback ใน `server/index.js` ทำหน้าที่แทน `.htaccess` เดิม)
- `BASE_PATH` ถูก bake ตอน `vite build` — **แก้แล้วต้อง build ใหม่** เปลี่ยนตอน runtime ไม่ได้
  และค่าฝั่ง server ต้องตรงกับตอน build เป๊ะ ๆ ไม่งั้น asset 404
- **หน้า login ต้องอยู่ที่ `/login` เสมอ** ห้ามย้าย

│   ├── config/

│   └── seed.js                # admin local (profile "seed" เท่านั้น)
├── Dockerfile
├── docker-compose.yml
└── docker-entrypoint.sh
